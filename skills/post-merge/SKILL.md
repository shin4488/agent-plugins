# マージ後の確認と整理

## 手順

1. GitHubで対象PRのマージ状態・取り込み先・マージコミットを確認する。ブランチが消えただけでマージ済みとは判断しない。
2. 作業ツリーと他のworktreeを確認する。残っている変更や他の作業を失わない状態で、取り込み先ブランチを更新する。

```bash
git fetch -p <remote>
git switch <取り込み先ブランチ>
git pull --ff-only <remote> <取り込み先ブランチ>
```

3. マージした変更が取り込まれたことを確認する。squash・rebaseでは作業ブランチのSHAがそのまま残るとは限らない。
4. 対象コミットに対応するCIを確認する。マージでデプロイが起動するリポジトリでは、その実行結果と変更に関係する公開動作も確認する。起動しない変更なら不要と記録する。
5. ローカル検証は `verify-changes` の結果を利用する。マージ時の競合解消・依存更新などで条件が変わった場合は、必要な範囲を再確認する。
6. 対象PRのブランチだけを整理する。進行中のPR・未公開コミット・他のworktreeから参照されていないか確認する。

```bash
git branch -d <作業ブランチ>
```

   `-d` が拒否した場合は理由を確認する。squash済みでも拒否されることがあるため、未マージと断定せず、強制削除もしない。remote側は自動削除済みなら操作不要。

## 報告

取り込み先、CI・必要なデプロイの結果、削除したブランチ、残したものと理由を伝える。依存PRがある場合はbaseを再確認し、必要な変更を依頼の範囲で行う。タグ・Releaseの作成は `release` が担当する。
