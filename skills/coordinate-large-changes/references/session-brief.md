# 指示書のひな形

まとめ役が各セッションの指示書を作るときに使う。会話を知らないセッションが、指示書だけを読んで作業を始め、終えられるようにする。

## 項目

| 項目 | 書くこと |
| --- | --- |
| 目的 | このセッションで作る1つの成果と、分割の図の中での位置 |
| 読むもの | 計画と進捗の記録、関係するファイル・資料。読まなくてよい範囲も書き、文脈を小さく保つ |
| 流れの図 | 作業の流れ、または変える構造を表すmermaidの図 |
| 作るもの | 変えるもの・足すテストなど、成果の中身 |
| 守ること | 守る条件、変えてはいけない範囲、このセッションで直さないもの（誤りに見える今の挙動など）。止めて報告する条件として、[SKILL.md](../SKILL.md) の「承認が要る操作と止める条件」のうちこのセッションにかかわるものと、指示書にない判断が要るとき |
| 完了の条件 | 合否の基準。例: 安全網の比較で差がない、既存のテストを書き換えずに通る、CIが成功する |
| 直す文書 | 変更に合わせて直す文書と、まとめ役の記録のうち更新する箇所 |
| PR | 基準のブランチ、依存するPR、本文に書く要点 |
| 終えるとき | まとめ役へ報告すること（PRのURL、CI、比較の結果、確かめていないこと、申し送り） |

## 始めるための1文

ユーザーが新しいセッションに貼るだけで始められるように、指示書の場所と、守ることと終えるときに従うことを含める。

例: 「リポジトリの `docs/plans/session-2a.md` の指示書を読み、その守ることと完了の条件に従って作業し、終えるときの報告まで行ってください。」
