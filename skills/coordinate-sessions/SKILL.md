# 作業を複数のセッションに分けて進める

作業を親セッションと子セッションに分けて進める。作業の大きさにかかわらず、ユーザーがこの進め方を選んだときに、全体をまとめる親セッションで使う。

変えてはいけない動作（守る条件）は、それにかかわる変更より前に検証の方法（変更の前後で結果を比べる、テストを足すなど）を用意し、変更のたびにその方法で確かめる。検証の方法は、変更していない状態では同じ結果になり、守る条件を破ると失敗することを確かめてから使う。守る条件のない調査では要らない。

計画・指示書・PRの本文・報告は [clear-writing](../clear-writing/SKILL.md) に従って書く。子セッションのブランチ・コミット・検証・PRは [create-branch](../create-branch/SKILL.md)・[commit](../commit/SKILL.md)・[verify-changes](../verify-changes/SKILL.md)・[create-pr](../create-pr/SKILL.md)、マージの後の反映と本番の確認は [post-merge](../post-merge/SKILL.md)、検証のためのテストの設計は [spec-based-testing](../spec-based-testing/SKILL.md) に従う。記録・指示書・引き継ぐことをIssueなど外部から見える場所に書くときは、[verify-changes](../verify-changes/SKILL.md#機密情報の扱い) の機密情報の扱いに従い、公開すべきでない情報を入れない。

## 役割

| 役割 | すること |
| --- | --- |
| ユーザー | 親セッションで計画の判断をする。子セッションを始め、子セッションと直接やりとりして、挙動の違いやPRを受け入れるかを決める。子セッションが終わったら親セッションに伝える |
| 親セッション | 計画・分割・指示書・記録・全体の状態を持つ。子セッションの作業と、成果を受け入れるかの判断はしない |
| 子セッション | 指示書に従って成果を作り、ユーザーに決めてほしいことは直接尋ねる。後続の子セッションに引き継ぐことがあれば指示書で示された場所に書き、マージの後の反映と本番の確認まで行う |

```mermaid
sequenceDiagram
    actor User as ユーザー
    participant Parent as 親セッション
    participant Child as 子セッション
    User->>Parent: 依頼する
    Parent->>User: 計画と、決めてほしいことの案・理由
    User->>Parent: 決める
    Parent->>User: 分割と、最初の指示書
    loop 子セッションごと（依存がなければ並行できる）
        User->>Child: 指示書で始める
        Child->>User: PR、検証の結果、決めてほしいこと
        User->>Child: 受け入れるかを決める
        Child->>User: マージの後の本番の確認と、終えるときの報告
        User->>Parent: 終わったと伝える
        Parent->>Parent: PR・CI・本番の事実を確かめ、記録を更新する
        Parent->>User: 全体の状態と、次の指示書
    end
    Parent->>User: 片付けの結果
```

## 親セッションの記録

親セッションは、次の項目を1つの記録にまとめる。親セッションの文脈が要約されたり、セッションが終わったりしても、記録から再開できるようにするため。置き場所はリポジトリの規約に従い、なければ計画のときにユーザーと決める。

| 項目 | 内容 |
| --- | --- |
| 計画 | 今の状態（根拠つき）と目標、守る条件と変わってよいもの、検証の方法、子セッションの分け方と依存関係 |
| 判断 | ユーザーが決めたことと、そのときに示した案と理由 |
| 進捗 | 子セッションごとの成果・PR・状態・CI・検証の結果・本番への反映 |

## 子セッションの分け方

子セッションは、レビューしてマージできるまとまりで分け、必要以上に細かく分けない。各PRは、単独でマージして本番へ反映できる状態にする。

## 子セッションを進める

親セッションは子セッションごとに指示書を作り、ユーザーが子セッションを始めるための指示を渡す。指示書はファイルでも、子セッションに貼る文章でもよい。使える環境では、セッションを起動する機能も使う。子セッションは親セッションのやりとりもこのskillも読まずに作業することがあるため、指示書だけで作業を始めて終えられるように、次を書く。

| 項目 | 書くこと |
| --- | --- |
| 目的 | 作る成果と、全体の中での位置 |
| 読むもの | 関係するファイル・資料と、読まなくてよい範囲 |
| 引き継ぐこと | 前の子セッションから引き継ぐことのうち、この子セッションにかかわるもの |
| 守ること | 守る条件と変えてはいけない範囲。守る条件にかかわる挙動の違いが見つかったときや、指示書にないことを決める必要があるときは、作業を止めてユーザーに尋ねること。親セッションの記録は直さないこと。外部から見える場所に書くときに、公開すべきでない情報を入れないこと |
| 完了の条件 | 合否の基準。後続の子セッションに引き継ぐことがあれば、それを書く場所 |

- 子セッションが終わったとユーザーから伝えられたら、記録の「進捗」を、PR・CIなどで確かめた事実をもとに更新する。そのうえで、全体の状態（完了したもの・次に始められるもの・残り）をユーザーに示し、次の指示書を作る。事実がPRや報告と食い違えば、記録を更新せずにユーザーに示す。
- 引き継ぐこと（未決の点・見つかった問題・前提の変化）は、子セッションごとに分けて書いてもらう。置き場所は計画のときにユーザーと決め、例えば、同じマシンならリポジトリの外のmdファイル、クラウドなら作業全体で1つのIssueへのコメントにする。親セッションはそれを読み、すでに始まっている子セッションにかかわるものは、ユーザーに示して伝えてもらう。

## 終える条件

- すべての子セッションの成果がマージされ、本番への反映と確認が済んでいる。反映しないものは理由を記録している。
- ユーザーの判断を待っていることや、後回しにした作業が残っていない。
- 作業のために用意した環境・一時データ・ブランチを、ほかの作業で使っていないことを確かめて片付けている。今後も使う見込みがあり、作り直すのが難しいものは残し、残したものの場所と理由をユーザーに伝えている。
