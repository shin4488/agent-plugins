# 作業を複数のセッションに分けて進める

作業を親セッションと子セッションに分けて進める。作業の大きさにかかわらず、ユーザーがこの進め方を選んだときに、全体をまとめる親セッションで使う。変えてはいけない動作（守る条件）は、変更を始める前に検証の方法を用意し、変更のたびにその方法で確かめる。

計画・指示書・PRの本文・報告は [clear-writing](../clear-writing/SKILL.md) に従って書く。子セッションのブランチ・コミット・検証・PRは [create-branch](../create-branch/SKILL.md)・[commit](../commit/SKILL.md)・[verify-changes](../verify-changes/SKILL.md)・[create-pr](../create-pr/SKILL.md)、マージの後の反映と本番の確認は [post-merge](../post-merge/SKILL.md)、検証のためのテストの設計は [spec-based-testing](../spec-based-testing/SKILL.md) に従う。

## 役割

| 役割 | すること |
| --- | --- |
| ユーザー | 親セッションで計画の判断をする。子セッションを始め、子セッションと直接やりとりして、挙動の違いやPRを受け入れるかを決める。子セッションが終わったら親セッションに伝える |
| 親セッション | 計画・分割・指示書・記録・全体の状態を持つ。子セッションの作業と、成果を受け入れるかの判断はしない |
| 子セッション | 指示書に従って成果を作り、判断が要る点はユーザーに直接示す。検証の結果・後続の子セッションに引き継ぐことをPRに書き、マージの後の反映と本番の確認まで行う |

```mermaid
sequenceDiagram
    actor User as ユーザー
    participant Parent as 親セッション
    participant Child as 子セッション
    User->>Parent: 依頼する
    Parent->>User: 計画と、判断が要る点の案・理由
    User->>Parent: 決める
    Parent->>User: 分割と、最初の指示書
    loop 子セッションごと（依存がなければ並行できる）
        User->>Child: 指示書で始める
        Child->>User: PR、検証の結果、判断が要る点
        User->>Child: 受け入れるかを決める
        Child->>User: マージの後の本番の確認と、終えるときの報告
        User->>Parent: 終わったと伝える
        Parent->>Parent: PR・CI・本番の事実を確かめ、記録を更新する
        Parent->>User: 全体の状態と、次の指示書
    end
    Parent->>User: 全体の比較と、片付けの結果
```

## 段階ごとの目的と完了の条件

手段は作業に合わせて選ぶ。完了の条件を満たすまで次の段階へ進まない。

| 段階 | 目的 | 完了の条件 |
| --- | --- | --- |
| 計画 | 今の状態を根拠つきで調べ、目標・守る条件・変わってよいもの・判断が要る点を分ける | 計画を記録し、判断が要る点がすべてユーザーの決定として記録されている |
| 検証の準備 | 守る条件が破られたら、変更した子セッション自身が気づけるようにする | 守る条件ごとに検証の方法（変更の前後で結果を比べる、テストを足すなど）があり、変更していない状態では同じ結果になり、守る条件を破ると失敗することを確かめている。守る条件にかかわる変更より前に用意する。守る条件のない調査では不要 |
| 分割 | 子セッションの分け方・順序・並行できる組を決める | 依存関係と並行できる組の図と、最初の子セッションの指示書がある |
| 進行 | 子セッションが成果を作り、ユーザーが受け入れる | 子セッションが終わるたびに、親セッションが事実を確かめて記録を更新している |
| 仕上げ | 全体で守る条件が保たれたことを確かめ、作業の跡を片付ける | 下の「終える条件」を満たしている |

子セッションは、レビューしてマージできるまとまりで分け、必要以上に細かく分けない。各PRは、単独でマージして本番へ反映できる状態にする。

## 親セッションの記録

親セッションは、次の項目を1つの記録にまとめる。親セッションの文脈が要約されたり、セッションが終わったりしても、記録から再開できるようにするため。置き場所はリポジトリの規約に従い、なければ計画のときにユーザーと決める。

| 項目 | 内容 |
| --- | --- |
| 計画 | 今の状態と根拠、目標、守る条件、変わってよいもの、検証の方法、分割の図 |
| 判断 | 判断が要った点、示した案と理由、ユーザーの決定 |
| 進捗 | 子セッションごとの成果・PR・状態・CI・検証の結果・本番への反映 |
| 引き継ぐこと | 後続の子セッションが知っておくべき未決の点・見つかった問題・前提の変化 |

記録を更新するのは親セッションだけにする。並行する子セッションが同じ記録を書き換えて競合しないよう、子セッションはPRに書き、親セッションがそこから記録へ移す。

## 子セッションを進める

親セッションは子セッションごとに指示書を作り、ユーザーが子セッションを始めるための指示を渡す。指示書はファイルでも、子セッションに貼る文章でもよい。使える環境では、セッションを起動する機能も使う。子セッションは親セッションのやりとりもこのskillも読まずに作業することがあるため、指示書だけで作業を始めて終えられるように、次を書く。

| 項目 | 書くこと |
| --- | --- |
| 目的 | 作る成果と、分割の図の中での位置 |
| 読むもの | 関係するファイル・資料と、読まなくてよい範囲 |
| 引き継ぐこと | 前の子セッションから引き継ぐことのうち、この子セッションにかかわるもの |
| 守ること | 守る条件と変えてはいけない範囲、下の「ユーザーが決めることと、止めるとき」のうちこの子セッションにかかわるもの。親セッションの記録は直さないこと |
| 完了の条件 | 合否の基準と、終えるときにPRに書くこと（検証の結果、確かめていないこと、後続に引き継ぐこと） |

- 子セッションが終わったとユーザーから伝えられたら、PRの状態・CI・本番への反映と確認の事実を確かめ、PRに書かれた内容とあわせて記録を更新する。事実がPRや報告と食い違えば、記録を更新せずにユーザーに示す。
- 引き継ぐことのうち、まだ始まっていない子セッションにかかわるものは、その子セッションの指示書に書く。すでに始まっている子セッションにかかわるものは、ユーザーに示し、その子セッションへ伝えてもらう。
- 記録を更新したら、全体の状態（完了したもの・次に始められるもの・残り）をユーザーに示し、次の指示書を作る。
- 並行した子セッションのPRは1つずつマージする。後のPRの子セッションは基準のブランチを取り込み、CIと検証を確かめ直してから、ユーザーに受け入れるかを尋ねる。

## ユーザーが決めることと、止めるとき

- 判断が要る点は、案と理由を示してユーザーに決めてもらう。親セッションで決まったことは、親セッションの記録に残す。質問をきっかけに、頼まれていない変更をしない。
- 守る条件にかかわる挙動の違いが見つかったとき、指示書にない判断が要るとき、検証が失敗したり実行できなかったりしたときは、作業を止めてユーザーに示す。挙動の違いは、仕様の言葉と具体的な場面（入力と、変更の前と後の結果）で示す。
- 誤りに見える今の挙動は直さずに記録し、直すかどうかを別の判断としてユーザーに示す。
- 本番のデータを書き換える操作はユーザーが実行する。そのまま貼って実行できるコマンドと、実行の前後に確かめることを渡す。本番へ反映する前に、直近の本番の状態を確かめる。

## 終える条件

- すべての子セッションの成果がマージされ、本番への反映と確認が済んでいる。反映しないものは理由を記録している。
- 並行した子セッションがあれば、すべてマージした後に並行の前と後をまとめて比べ（親セッションか、そのための子セッションで行う）、差がないか、ユーザーが受け入れた差だけである。
- 未決の判断と、引き継ぐことに残った作業がない。
- 作業用の環境・一時データ・ブランチを、ほかの作業で使っていないことを確かめて片付けた。手間をかけて取得したデータは残し、場所と理由を記録している。
