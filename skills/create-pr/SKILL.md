# PRを作成・更新する

会話を読んでいないレビュアーが、何が変わり、何を確認すればよいか判断できるPRにする。

## 進め方

- 対象リポジトリ・base・作業ブランチ・既存PRを確認する。同じ変更のPRがあれば更新し、重複作成しない。
- 必要なブランチ作成・コミットは `create-branch` と `commit` の手順を使う。`verify-changes` で検証した後に、コード・依存関係・設定が変わっていないか確認する。変わった場合は、影響する検査をやり直す。
- 差分全体を見直し、説明できる一つの目的にまとめる。複数PRが必要なら、依存関係とマージ順を明示する。
- 依頼された範囲でブランチをpushし、PRを作成・更新する。本文はファイルまたは構造化された引数で渡し、改行を保つ。
- 作成後、URL・base・差分・CIの状態を確認する。PR作成だけでマージしない。

## 本文に含める内容

リポジトリのPRテンプレートを優先する。なければ、変更の規模に合わせて以下を短く説明する。

| 内容 | 書くこと |
| --- | --- |
| 変更 | 問題と、変更後の動作。必要なら具体的な入力・結果の例 |
| 検証 | 実行した確認と結果、実行できなかった範囲 |
| 依存・注意点 | 先に必要なPR、導入操作、残る作業がある場合だけ |

作業の時系列や採用しなかった案を並べない。変更範囲が変わったら、タイトルと本文を最終的な内容に書き直す。自動生成の署名を付ける規約がある場合は、実際に利用したツールを表記する。
